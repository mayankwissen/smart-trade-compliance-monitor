Checking Criteria: How Fake Trades Are Detected

Built by: Mayank Gupta AI Model: Claude Sonnet 4.6 Backend: detector.py
The system uses 4 deterministic algorithms to scan every trader's order history. Each algorithm checks specific mathematical thresholds against the raw trade data. A trade cluster is flagged as suspicious only when all required criteria pass simultaneously. Claude AI then reads the pre-computed evidence and writes the legal rationale — it does NOT decide whether trades are suspicious. The math does.
Pattern 1
LAYERING
Flooding the order book with fake buy orders, then selling at the inflated price
1

Group trades by Trader + Instrument

All orders by the same trader_id on the same instrument are collected into one group.

2

Calculate Cancel Ratio

cancel_ratio = cancelled_orders / total_orders
Example: 12 cancelled out of 14 total → 12/14 = 0.857 (85.7%)

3

Calculate Sigma (Population Z-Score)

Mean and std-dev are computed live from all traders in the database (≥5 trades each).
sigma = (cancel_ratio - pop_mean) / pop_std
Example with pop_mean ≈ 0.20, pop_std ≈ 0.08: (0.857 - 0.20) / 0.08 ≈ 8.2σ above the live population

4

Check All 3 Criteria — ALL must pass

Cancel ratio above threshold + Sigma above threshold + At least 1 executed SELL

cancel_ratio Greater than 55% 85.7% REQUIRED ✓
sigma Greater than 2.0σ ~8.2σ REQUIRED ✓

Pattern 2
SPOOFING
Placing a massive order to move the market, then cancelling it before anyone fills it
1

Find orders larger than 40,000 shares

Only large orders can materially impact NSE order book depth. order_size > 40,000

2

Check cancel speed

Was this large order cancelled in under 600 milliseconds? cancel_time_ms < 600
Human reaction time minimum: ~200ms. Sub-600ms cancellation = algorithmic, not human.

3

Both criteria must be true simultaneously

A huge order cancelled in the blink of an eye = no intention of ever filling it.

Pattern 3
WASH TRADING
Buying and selling the same stock using two different accounts you control
1

Find same trader_id across different account_ids

The same person trading via two accounts: trader_id matches, account_id differs

2

Check for matching BUY and SELL on same instrument

Same stock, same size (within 10% tolerance): size_difference < 10%

3

Check the time window

BUY and SELL happen within 30 seconds of each other: time_diff < 30 seconds

Scoring
HOW CONFIDENCE IS SCORED (0–100)
A mathematical score passed to Claude to anchor its triage verdict

Every alert gets a pre-computed confidence score before Claude even sees it. Five evidence dimensions are each scored 0–100, then blended using pattern-specific weights. The final score is clamped to 52–97 (never 0 or 100 — the system acknowledges uncertainty).

Dimension Variable Formula (→ 0–100) What it measures
Cancel Ratio cr_score min(100, (cancel_ratio − 0.70) / 0.28 × 100) How far above 70% cancel rate the trader is
Sigma sig_score min(100, (sigma − 2.0) / 12.0 × 100) Statistical distance from the live population baseline
Cancel Speed timing_score min(100, (600 − cancel_ms) / 590 × 100) How much faster than 600ms the cancellations are (50 if no cancel time)
Order Volume vol_score min(100, (order_size − 10,000) / 70,000 × 100) Notional size of the suspicious orders
Sample Size sample_score min(100, total_orders / 15 × 100) Statistical reliability — more trades = more confidence

Weights reflect what matters most for each pattern type:

Pattern Cancel Ratio Sigma Cancel Speed Order Volume Sample Size
LAYERING 35% 25% 20% 10% 10%
SPOOFING 15% 20% 30% 25% 10%
WASH TRADING 0% 0% 10% 30% 60%
PUMP & DUMP 0% 25% 0% 40% 35%
raw = Σ (weight[i] × score[i]) ← weighted sum across 5 dimensions
final = clamp(raw, 52, 97) ← never 0 or 100 — always uncertain

Example — T-1042 LAYERING: cr=90, sig=52, timing=85, vol=40, sample=93
raw = 0.35×90 + 0.25×52 + 0.20×85 + 0.10×40 + 0.10×93 = 31.5+13+17+4+9.3 = 74.8
confidence = 75%
ANCHORED
Why this matters: The score is passed to Claude as confidence_hint. Claude's JSON output is pre-seeded with this value so even if the AI reasoning varies, the numeric confidence stays anchored to the mathematical evidence — not Claude's mood. Scores below ~60 push Claude toward DISMISS; above ~75 toward ESCALATE.
Severity
HOW SEVERITY IS ASSIGNED
Each alert is tagged HIGH or MEDIUM by the detector before Claude triages it

Severity is set deterministically by detector.py — Claude does not decide it. It feeds into case prioritisation (P1 vs P2), SLA breach dates, and escalation routing.

HIGH SEVERITY

LAYERING — when cancel_ratio > 0.80 (above 80%)
SPOOFING — always HIGH (any qualifying order = severe)
PUMP & DUMP — always HIGH (intent to harm other investors)

→ Case priority: P1 · SLA breach: T+15 days

⚡ Key Design Decision — Math First, AI Second

The detection engine does not ask Claude AI whether a trade is suspicious. Claude would be unreliable and expensive for this task ($0.045 per call if raw trades were sent). Instead, the system proves manipulation mathematically using cancel ratios, sigma scores, and timing thresholds — then sends Claude only the pre-computed evidence (~280 tokens) to write the legal rationale. This achieves 97% token savings ($0.00014 per call) while producing SEBI-quality verdicts that cite the exact regulation violated.
