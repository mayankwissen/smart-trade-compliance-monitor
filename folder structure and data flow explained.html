03 How Data Is Loaded — On Startup vs On Refresh
There are two ways data gets into the system:
(A) Startup auto-seed — happens automatically when the Flask server starts
(B) Manual refresh — triggered by the "Refresh Live Data" button or POST /api/refresh-data
A

Startup Auto-Seed (app.py runs on Render boot)

When Render starts the server, app.py runs with app.app_context() block which calls:

1. init_db() — creates all 5 tables if they don't exist
2. seed_from_csv() — checks if trades table is empty. If empty, fetches live NSE prices via yfinance and generates ~407 trades. If yfinance fails, falls back to trades_sample.csv
3. Auto-detection — runs all 4 detectors immediately, inserts any alerts found

Result: Data is ready within seconds of Render waking up. No manual click needed.

app.py → database.py → market_data.py → detector.py
B

Manual Refresh — "Refresh Live Data" button

Calls POST /api/refresh-data in app.py which:

1. Wipes all 4 tables (trades, alerts, triage_results, escalations)
2. Calls market_data.py → fetch_real_prices() — gets live prices for 20 NSE stocks via yfinance
3. Calls generate_realistic_trades(prices) — generates ~407 new trades at today's live prices
4. Inserts all trades into SQLite
5. Automatically runs POST /api/replay/start to detect patterns
6. Returns: {"trades_inserted": 407, "prices_used": {"HDFCBANK": 748.0, ...}}

app.py → market_data.py → SQLite
# market_data.py — How live NSE prices are fetched NSE_SYMBOLS = { 'HDFCBANK': 'HDFCBANK.NS', # .NS suffix = NSE listing on Yahoo Finance 'RELIANCE': 'RELIANCE.NS', 'TCS': 'TCS.NS', ... 20 stocks total ... } def fetch_real_prices(): # Step 1: Check 5-minute cache (avoids hitting Yahoo Finance every call) if _price_cache and (time.time() - _cache_ts) < 300: return _price_cache # Step 2: For each stock, fetch last 5 days of 1-minute candles for symbol, ticker in NSE_SYMBOLS.items(): data = yf.Ticker(ticker) hist = data.history(period='5d', interval='1m') # Step 3: Take the last closing price as "current price" prices[symbol] = { 'current': hist['Close'].iloc[-1], # e.g. ₹748.00 'high': hist['High'].max(), 'low': hist['Low'].min(), } def generate_realistic_trades(prices): # Step 4: Generate ~300 random trades for 50 normal traders at live prices # Step 5: Inject 4 suspicious clusters (LAYERING, SPOOFING, WASH, PUMP) # Step 6: All timestamps set to last 3 real trading days (Mon-Fri) return sorted(trades, key=lambda x: x['timestamp'])
04 How Pattern Detection Works — detector.py
1

ingestor.py — Load all trades from DB

load_trades() runs SELECT * FROM trades and returns all rows as dictionaries.

ingestor.py
2

Group by every trader+instrument combination

get_all_trader_instrument_pairs() runs SELECT DISTINCT trader_id, instrument FROM trades. With 50 traders and 20 stocks, this gives ~330 pairs to scan.

ingestor.py
3

Run all 4 detectors on each pair

For each (trader_id, instrument) pair, detector.py → run_all_detectors() runs all 4 functions. Each function filters the trades for just that pair and checks the mathematical criteria. If criteria pass → creates an alert dict.

detector.py
4

Deduplicate and store alerts

alert_exists() checks if an alert for this exact (trader_id, instrument, pattern_type) already exists in DB. If not, inserts it. This prevents duplicate alerts on repeated detection runs.

database.py → app.py
# app.py — POST /api/replay/start (the "Run Detectors" button) @app.route("/api/replay/start", methods=["POST"]) def replay_start(): trades = load_trades() # ingestor.py — all trades from DB pairs = get_all_trader_instrument_pairs() # ~330 unique combinations alerts_stored = 0 conn = get_db() for trader_id, instrument in pairs: # scan every pair alerts = run_all_detectors(trader_id, instrument, trades) for alert in alerts: if not alert_exists(conn, trader_id, instrument, alert["pattern_type"]): conn.execute("INSERT INTO alerts ...", (...)) alerts_stored += 1 conn.commit() return jsonify({"alerts_detected": alerts_stored, "pairs_scanned": len(pairs)})
05 Exactly What Gets Sent to Claude API — triage.py
Key design decision: Claude is NOT sent raw trade rows. It receives only pre-computed statistics. This cuts tokens from ~15,000 to ~280 per call — a 97% reduction. Claude's job is to write the legal rationale, not to detect patterns.
1

Frontend calls POST /api/triage/<alert_id>

User clicks "Triage This Alert". The frontend sends a POST request to the backend with the alert ID.

AlertDetail.js → app.py
2

app.py fetches the alert from DB and calls triage_alert()

Reads the alert row from SQLite (alert_id, trader_id, instrument, pattern_type, cancel_ratio, sigma, evidence_summary). Passes it to triage.py → triage_alert(alert).

app.py → triage.py
3

triage.py builds the prompt and calls Claude API

Two parts: (A) System prompt — sets Claude's persona as NSE CCO. (B) User prompt — the alert data as ~280 tokens. Sent via anthropic.Anthropic().messages.create().

triage.py → Anthropic API
4

Claude returns 8-field JSON → saved to triage_results table

Response parsed with json.loads(). Real token counts read from response.usage.input_tokens and response.usage.output_tokens. All 8 fields + metrics stored in DB.

triage.py → database.py
5

If ESCALATE → workflows.py fires 4 actions

Case created, Slack notified, email sent, watchlist flagged. All logged to escalations table.

app.py → workflows.py

06 What Happens After Claude Says ESCALATE — workflows.py
1

create_compliance_case()

Generates case ID (COMP-XXXX), writes a JSON case file to cases/ folder, inserts CASE_CREATED row into escalations table. Assigns to "Surveillance Desk L2".

2

send_slack_notification()

POSTs a rich Slack block message to the configured webhook URL. Includes verdict, rationale, case ID, recommended action. Inserts SLACK_NOTIFIED row into escalations table.

3

send_email_notifications()

Reads all active subscriber emails from DB. Calls emailer.py → send_alert_email() which POSTs to SendGrid HTTP API (port 443 — SMTP ports are blocked on Render). Sends styled HTML email to each subscriber.

4

flag_watchlist()

Inserts WATCHLIST_FLAGGED row into escalations table with 72-hour monitoring window and reason. Alerts table updated: status → ESCALATED.

08 Quick Answers for Judge Questions
Judge asksAnswer
"Where does the trade data come from?" Generated synthetically by market_data.py at real live NSE prices fetched from Yahoo Finance via yfinance. 4 suspicious clusters are injected deliberately. Timestamps are last 3 real trading days.
"How does it refresh with new data?" POST /api/refresh-data wipes all tables, fetches today's live NSE prices, generates ~407 new trades at those prices, re-runs detection. Old data is gone, fresh data in.
"What exactly does Claude receive?" Only: alert_id, trader_id, instrument, severity, pattern_type, evidence_summary (1 sentence), cancel_ratio (float), sigma (float). Total ~280 tokens. NOT raw trade rows.
"Why not send raw trades to Claude?" 416 trades × 35 tokens = 14,560 tokens = $0.045/call. With pre-computed stats: 280 tokens = $0.00014/call. 97% cheaper. Same verdict quality.
"How do you know Claude's output is correct?" Claude doesn't decide if a trade is suspicious — the mathematical detectors do. Claude only writes the legal rationale for an alert that already passed statistical thresholds.
"What if Claude returns bad JSON?" triage.py strips markdown fences, then uses json.loads() inside try/except JSONDecodeError. If parsing fails, returns a 500 error with the raw text for debugging.
"How is the database created?" database.py → init_db() runs on server startup. Creates all 5 tables if they don't exist. Runs column migrations safely (ALTER TABLE skips existing columns).
"Why SQLite and not PostgreSQL?" Zero config for a demo. Schema is drop-in compatible with PostgreSQL. The only difference would be the connection string in database.py.
"How does the frontend know which backend to call?" api.js → API_BASE checks window.location.hostname. If localhost → http://localhost:5000. If production → the Render backend URL. No environment files needed.
"How does real-time price update work?" Header.js calls GET /api/market-prices every 60 seconds. Backend has a 5-minute in-memory cache to avoid hammering Yahoo Finance. If yfinance fails, hardcoded fallback prices are used.
